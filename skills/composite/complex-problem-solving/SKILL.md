# 复杂问题诊断

适用于：多个问题同时出现、各部门/变量相互影响、资源不足以平均处理的复杂系统。

## Workflow
1. 调查事实，列出问题清单与相互影响。
2. 找主要矛盾：哪个问题的变化最可能带动其他问题？
3. 分析内部条件与外部条件，避免只把原因归咎于环境或个人。
4. 检查不同问题的性质，避免统一处方。
5. 以中心工作为轴安排其他任务，明确优先级与节奏。

## Stop conditions
- 如果所谓“主要矛盾”只是直觉且无证据，退回调查步骤。
- 如果问题之间相互独立，不要强行构造单一中心。

## Evidence rule
若回答声称某一步直接来自具体原文，应通过 `retrieval/` 或 `evidence/` 核验；否则表述为“本项目基于上游 Skill 做的现代迁移”。
