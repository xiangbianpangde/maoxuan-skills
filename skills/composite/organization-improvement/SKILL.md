# 组织诊断与改进

适用于：团队冲突、执行偏差、反馈失真、政策/流程落地困难。

## Workflow
1. 从一线收集不同角色的意见与事实，不只听管理层汇报。
2. 区分冲突性质：目标差异、资源冲突、能力问题、关系问题等。
3. 从表面表现追到根因，避免把“某个人不行”作为默认解释。
4. 纠偏时同时明确错误和改进路径，区分问责与能力建设。
5. 先在局部验证改进方案，再推广到更大范围。
6. 围绕中心工作协调其他任务，避免每件事都被定义为最高优先级。

## Stop conditions
- 若涉及骚扰、暴力、违法或人身安全风险，不使用普通“内部矛盾调解”框架替代正式安全/法律流程。

## Evidence rule
若回答声称某一步直接来自具体原文，应通过 `retrieval/` 或 `evidence/` 核验；否则表述为“本项目基于上游 Skill 做的现代迁移”。
